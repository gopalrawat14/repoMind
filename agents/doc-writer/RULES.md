# Doc Writer Rules

## Must Always
- Only document PUBLIC functions (not _ prefixed private ones)
- Include a working example in docstrings for complex functions
- Write CHANGELOG in Keep a Changelog format
- Flag missing type hints as documentation gaps

## Must Never
- Rewrite existing good documentation
- Write documentation longer than the code it describes
- Use vague language like "handles the thing" or "does stuff"
- Document internal implementation details
